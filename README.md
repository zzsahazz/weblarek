# Проектная работа «Веб-ларёк»

## Описание проекта

«Веб-ларёк» — интернет-магазин, в котором пользователь может просматривать каталог товаров, добавлять товары в корзину и оформлять заказ.

Проект реализован с использованием архитектурного подхода MVP (Model–View–Presenter) и событийной модели взаимодействия между компонентами.

## Технологии

- HTML5
- SCSS
- TypeScript
- Vite

## Функциональность

- Загрузка каталога товаров с сервера.
- Отображение карточек товаров.
- Просмотр подробной информации о товаре.
- Добавление товаров в корзину.
- Удаление товаров из корзины.
- Подсчёт количества товаров и общей стоимости.
- Выбор способа оплаты.
- Ввод адреса доставки.
- Ввод контактных данных покупателя.
- Валидация данных перед оформлением заказа.
- Отправка заказа на сервер.
- Отображение результата оформления заказа.

## Архитектура проекта

В проекте используется архитектура MVP (Model–View–Presenter), которая разделяет приложение на три основных слоя.

### Model — модели данных

Модели отвечают за хранение, изменение и предоставление данных приложения.

В проекте используются:

- `CatalogModel` — управление каталогом товаров и выбранным товаром.
- `BasketModel` — управление содержимым корзины и расчёт стоимости.
- `BuyerModel` — хранение и валидация данных покупателя.

### View — представление

Компоненты View отвечают за отображение информации и взаимодействие с пользователем.

Они отображают данные и передают действия пользователя через события или функции обратного вызова. Бизнес-логика приложения в компонентах представления не выполняется.

### Presenter — посредник

Роль Presenter выполняет файл `main.ts`.

Он связывает модели и представления, обрабатывает события, обновляет интерфейс, управляет переходами между формами и организует отправку заказа на сервер.

### Взаимодействие компонентов

1. Пользователь выполняет действие в интерфейсе.
2. View-компонент генерирует событие или вызывает переданную функцию обратного вызова.
3. Presenter обрабатывает действие.
4. При необходимости Presenter обращается к модели.
5. Модель изменяет данные и генерирует событие об изменении состояния.
6. Presenter получает событие и обновляет соответствующее представление.

Для обмена событиями используется `EventEmitter`.

## Базовые классы

### Component

Базовый класс для компонентов View.

Предоставляет общую функциональность для работы с HTML-элементами и обновления интерфейса. Остальные компоненты представления наследуются от него.

### Api

Базовый класс для выполнения HTTP-запросов к серверу.

Предоставляет методы:

- `get()` — получение данных.
- `post()` — отправка данных.

### EventEmitter

Класс для организации событийного взаимодействия между компонентами приложения.

Позволяет подписываться на события, генерировать их и обрабатывать изменения состояния приложения.

## Типы данных

Основные интерфейсы, типы и перечисления проекта находятся в `src/types/index.ts`.

### ApiPostMethods

Тип HTTP-методов для отправки запросов:

```ts
export type ApiPostMethods = 'POST' | 'PUT' | 'DELETE';
```

### IApi

Интерфейс базового API-клиента.

Описывает методы:

- `get<T>(uri)` — получение данных с сервера.
- `post<T>(uri, data, method?)` — отправка данных на сервер.

### BuyerErrors

Тип для хранения ошибок валидации данных покупателя:

```ts
export type BuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Позволяет хранить сообщения об ошибках для отдельных полей интерфейса `IBuyer`.

### TPayment

Перечисление способов оплаты:

```ts
export enum TPayment {
    CARD = 'card',
    CASH = 'cash',
}
```

- `CARD` — оплата картой.
- `CASH` — оплата наличными.

### IProduct

Интерфейс товара:

```ts
export interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

- `id` — уникальный идентификатор товара.
- `description` — подробное описание товара.
- `image` — изображение товара.
- `title` — название товара.
- `category` — категория товара.
- `price` — цена в синапсах; `null`, если товар нельзя купить.

### IBuyer

Интерфейс данных покупателя:

```ts
export interface IBuyer {
    payment: TPayment | '';
    email: string;
    phone: string;
    address: string;
}
```

- `payment` — выбранный способ оплаты.
- `email` — электронная почта.
- `phone` — номер телефона.
- `address` — адрес доставки.

### IProducts

Интерфейс ответа сервера с каталогом товаров:

```ts
export interface IProducts {
    total: number;
    items: IProduct[];
}
```

- `total` — общее количество товаров.
- `items` — массив товаров.

### IOrder

Интерфейс данных заказа:

```ts
export interface IOrder {
    payment: TPayment;

}
```

### IOrderResult

Интерфейс результата оформления заказа:

```ts
export interface IOrderResult {

    total: number;
}
```

### TCard

Тип данных для карточки товара:

```ts
export type TCard = Pick<IProduct, 'title' | 'price'> & {
    category?: string;

    description?: string;
```

### TCardCatalog

Тип данных карточки товара в каталоге:

```ts
export type TCardCatalog = TCard & Pick<IProduct, 'category' | 'image'>;
```

### ICardActions

Интерфейс действий карточки:

```ts
export interface ICardActions {
    onClick?: () => void;
```

## Модели данных (Model)

### CatalogModel

Класс `CatalogModel` отвечает за хранение и управление каталогом товаров, а также за выбор товара для подробного просмотра.

**Основные данные:**

- `productList` — массив товаров каталога.
- `chosenProduct` — выбранный товар.

**Конструктор:**

`constructor(events: IEvents)` — принимает систему событий.

**Методы:**

- `saveProducts(products: IProduct[])` — сохраняет массив товаров и генерирует событие `catalog:changed`.
- `getProducts()` — возвращает массив товаров.
- `findProduct(productId: string)` — ищет товар по идентификатору.
- `chooseProduct(product: IProduct | null)` — устанавливает выбранный товар и генерирует событие `preview:changed`.
- `getChosenProduct()` — возвращает выбранный товар.

**События:**

- `catalog:changed` — генерируется при сохранении каталога товаров.
- `preview:changed` — генерируется при изменении выбранного товара.

События моделей не передают данные в качестве аргументов. Для получения актуального состояния Presenter обращается к соответствующим методам модели.

### BasketModel

Класс `BasketModel` отвечает за управление товарами в корзине и расчёт общей стоимости.

**Основные данные:**

- `basketProducts` — массив товаров в корзине.
- `events` — система событий.

**Конструктор:**

`constructor(events: IEvents)` — принимает систему событий.

**Методы:**

- `getProducts()` — возвращает товары корзины.
- `addProduct(product: IProduct)` — добавляет товар в корзину.
- `removeProduct(productId: string)` — удаляет товар по идентификатору.
- `clearBasket()` — очищает корзину.
- `getTotalPrice()` — рассчитывает общую стоимость товаров.
- `getProductCount()` — возвращает количество товаров в корзине.
- `hasProduct(productId: string)` — проверяет наличие товара в корзине.

**События:**

- `basket:changed` — генерируется при изменении содержимого корзины.

Событие не передаёт массив товаров. Presenter получает актуальные данные через `basket.getProducts()` и другие методы модели.

### BuyerModel

Класс `BuyerModel` отвечает за хранение данных покупателя и их валидацию перед оформлением заказа.

**Основные данные:**

- `payment` — выбранный способ оплаты.
- `address` — адрес доставки.
- `email` — электронная почта.
- `phone` — номер телефона.
- `events` — система событий.

**Конструктор:**

`constructor(events: IEvents)` — принимает систему событий.

**Методы:**

- `updateBuyerData(data: Partial<IBuyer>)` — обновляет переданные данные покупателя.
- `getBuyerData()` — возвращает текущие данные покупателя.
- `clearBuyerData()` — очищает данные покупателя.
- `validateBuyerData()` — проверяет обязательные поля и возвращает объект ошибок типа `BuyerErrors`.

**Проверки валидации:**

- Выбран ли способ оплаты.
- Указан ли адрес доставки.
- Заполнена ли электронная почта.
- Заполнен ли номер телефона.

**События:**

- `buyer:changed` — генерируется при изменении или очистке данных покупателя.

Событие не передаёт объект покупателя. Presenter получает актуальные данные через `buyer.getBuyerData()` и `buyer.validateBuyerData()`.

## API-сервис

### ApiService

Класс `ApiService` является дополнительным уровнем взаимодействия между приложением и API.

Он использует интерфейс `IApi` и предоставляет методы для работы с данными интернет-магазина.

**Конструктор:**

`constructor(api: IApi)` — принимает экземпляр API-клиента.

**Методы:**

- `getProducts(): Promise<IProducts>` — отправляет GET-запрос на `/product/` и получает каталог товаров.
- `createOrder(order: IOrder): Promise<IOrderResult>` — отправляет POST-запрос на `/order/` с данными заказа и получает результат оформления.

## Компоненты представления (View)

### Gallery

Класс `Gallery` отвечает за отображение карточек товаров в каталоге.

**Сеттеры:**

- `catalog(items: HTMLElement[])` — заменяет содержимое галереи переданными карточками с помощью `replaceChildren()`.

Компонент не создаёт карточки и не загружает товары с сервера. Он только отображает переданные HTML-элементы.

### Card

Базовый абстрактный класс карточки товара.

Используется для повторного применения общей логики отображения названия и цены в разных видах карточек.

**Основные элементы:**

- `titleElement` — элемент названия товара.
- `priceElement` — элемент цены товара.

**Сеттеры:**

- `title(value: string)` — устанавливает название товара.
- `price(value: number | null)` — устанавливает цену товара. При значении `null` отображается текст, предусмотренный настройками проекта.

### CardCatalog

Класс `CardCatalog` отвечает за отображение карточки товара в каталоге.

**Конструктор:**

`constructor(container: HTMLElement, actions?: ICardActions)` — принимает HTML-элемент карточки и необязательный объект действий.

**Сеттеры:**

- `category(value: string)` — устанавливает категорию товара и соответствующий CSS-модификатор.
- `image(value: string)` — устанавливает изображение товара.

Также наследует сеттеры `title` и `price` от класса `Card`.

При передаче обработчика `onClick` устанавливает его на карточку.

### CardPreview

Класс `CardPreview` отвечает за отображение подробной информации о товаре в модальном окне.

**Конструктор:**

`constructor(events: IEvents, container: HTMLElement)` — принимает систему событий и HTML-элемент карточки.

**Сеттеры:**

- `category(value: string)` — устанавливает категорию товара.
- `image(value: { src: string; alt: string })` — устанавливает изображение и альтернативный текст.
- `description(value: string)` — устанавливает описание товара.
- `buttonText(value: string)` — изменяет текст кнопки действия.
- `buttonDisabled(value: boolean)` — управляет доступностью кнопки.

Также наследует сеттеры `title` и `price` от класса `Card`.

**События:**

- `preview:button-click` — генерируется при нажатии на кнопку действия с товаром.

Компонент не добавляет и не удаляет товары самостоятельно. Этим занимается Presenter совместно с `BasketModel`.

### Header

Класс `Header` отвечает за отображение шапки приложения.

**Основные элементы:**

- счётчик количества товаров в корзине;
- кнопка открытия корзины.

**Конструктор:**

`constructor(container: HTMLElement, onBasketClick: () => void)` — принимает HTML-элемент шапки и функцию обратного вызова для открытия корзины.

**Сеттеры:**

- `counter(value: number)` — устанавливает количество товаров в корзине.

### Modal

Класс `Modal` отвечает за управление модальным окном приложения.

**Основные элементы:**

- `closeButton` — кнопка закрытия.
- `contentElement` — контейнер содержимого модального окна.

**Конструктор:**

`constructor(container: HTMLElement)` — принимает HTML-контейнер модального окна и устанавливает обработчики закрытия.

**Сеттер:**

- `content(element: HTMLElement)` — заменяет содержимое модального окна переданным HTML-элементом.

**Методы:**

- `open()` — открывает модальное окно, добавляя класс `modal_active`.
- `close()` — закрывает модальное окно и удаляет класс `modal_active`.

Модальное окно закрывается при нажатии на кнопку закрытия, фон окна или клавишу `Escape`.

### BasketItem

Класс `BasketItem` отвечает за отображение одного товара в корзине.

**Основные элементы:**

- `indexElement` — элемент порядкового номера.
- `deleteButton` — кнопка удаления товара.

**Конструктор:**

`constructor(container: HTMLElement, onDelete: () => void)` — принимает HTML-элемент карточки и функцию обратного вызова для удаления товара.

**Сеттер:**

- `index(value: number)` — устанавливает порядковый номер товара.

Компонент вызывает переданную функцию `onDelete`, а фактическое удаление выполняется через `BasketModel`.

### BasketView

Класс `BasketView` отвечает за отображение содержимого корзины.

**Основные элементы:**

- `listElement` — контейнер списка товаров.
- `totalElement` — элемент общей стоимости.
- `orderButton` — кнопка перехода к оформлению заказа.

**Конструктор:**

`constructor(container: HTMLElement, onOrder: () => void)` — принимает HTML-элемент корзины и функцию обратного вызова для перехода к оформлению заказа.

**Сеттеры:**

- `items(items: HTMLElement[])` — отображает переданные карточки товаров.
- `total(value: number)` — отображает общую стоимость товаров.
- `orderDisabled(value: boolean)` — управляет доступностью кнопки оформления заказа.

### OrderForm

Класс `OrderForm` отвечает за первую часть оформления заказа: выбор способа оплаты и ввод адреса доставки.

**Основные элементы:**

- кнопки выбора оплаты картой и наличными;
- поле ввода адреса;
- кнопка перехода к следующему этапу;
- элемент отображения ошибок.

**Конструктор:**

`constructor(events: IEvents, container: HTMLFormElement)` — принимает систему событий и HTML-форму.

**Сеттеры:**

- `payment(value: TPayment)` — устанавливает способ оплаты.
- `address(value: string)` — заполняет поле адреса.
- `errors(value: string)` — устанавливает текст ошибок.
- `valid(value: boolean)` — управляет доступностью кнопки перехода к следующему этапу.

**События:**

- `order:payment-change` — генерируется при изменении способа оплаты.
- `order:address-change` — генерируется при изменении адреса доставки.
- `order:submit` — генерируется при отправке первой формы.

### ContactsForm

Класс `ContactsForm` отвечает за вторую часть оформления заказа: ввод электронной почты и номера телефона.

**Основные элементы:**

- поле электронной почты;
- поле номера телефона;
- кнопка отправки заказа;
- элемент отображения ошибок.

**Конструктор:**

`constructor(events: IEvents, container: HTMLFormElement)` — принимает систему событий и HTML-форму.

**Сеттеры:**

- `email(value: string)` — заполняет поле электронной почты.
- `phone(value: string)` — заполняет поле телефона.
- `errors(value: string)` — устанавливает текст ошибок.
- `valid(value: boolean)` — управляет доступностью кнопки отправки заказа.

**События:**

- `contacts:email-change` — генерируется при изменении электронной почты.
- `contacts:phone-change` — генерируется при изменении номера телефона.
- `contacts:submit` — генерируется при отправке формы.

### Success

Класс `Success` отвечает за отображение результата успешного оформления заказа.

**Основные элементы:**

- `descriptionElement` — элемент с информацией о списанной сумме.
- `closeButton` — кнопка закрытия окна.

**Конструктор:**

`constructor(container: HTMLElement, onClose: () => void)` — принимает HTML-элемент окна успешного оформления и функцию обратного вызова для закрытия модального окна.

**Сеттер:**

- `total(value: number)` — отображает сумму списанных синапсов.

## Presenter — main.ts

Файл `main.ts` выполняет роль Presenter и связывает модели и представления.

В нём создаются экземпляры моделей, API-клиента и View-компонентов, настраиваются подписки на события и определяется логика взаимодействия между ними.

### Инициализация приложения

При запуске создаются:

- `EventEmitter` — система событий.
- `CatalogModel` — модель каталога.
- `BasketModel` — модель корзины.
- `BuyerModel` — модель покупателя.
- `Api` — базовый API-клиент.
- `ApiService` — сервис взаимодействия с сервером.
- `Gallery` — представление каталога.
- `Header` — шапка приложения.
- `Modal` — модальное окно.

### Функции Presenter

- `getRequiredElement()` — получает HTML-элемент по селектору и проверяет его наличие.
- `updateBasketCounter()` — обновляет счётчик товаров в корзине.
- `updateOrderForm()` — обновляет ошибки и состояние первой формы.
- `updateContactsForm()` — обновляет ошибки и состояние второй формы.
- `showSuccess(total)` — отображает окно успешного оформления заказа.
- `renderCatalog(products)` — создаёт карточки каталога и передаёт их в `Gallery`.
- `openPreview(product)` — открывает подробную информацию о выбранном товаре.
- `openBasket()` — открывает корзину и отображает её содержимое.
- `openOrder()` — открывает первую форму оформления заказа.
- `openContacts()` — проверяет данные первой формы и открывает форму контактных данных.
- `submitOrder()` — выполняет итоговую проверку, формирует заказ, отправляет его на сервер и обрабатывает результат.

### События приложения

Взаимодействие между моделями, представлениями и Presenter организовано через систему событий `EventEmitter`.

#### События моделей

| Событие | Источник | Когда генерируется |
|---|---|---|
| `catalog:changed` | `CatalogModel` | При сохранении каталога товаров. |
| `preview:changed` | `CatalogModel` | При изменении выбранного товара. |
| `basket:changed` | `BasketModel` | При изменении содержимого корзины. |
| `buyer:changed` | `BuyerModel` | При изменении или очистке данных покупателя. |

События моделей генерируются без передачи дополнительных данных. Presenter самостоятельно получает актуальное состояние через методы соответствующих моделей.

#### События представлений

| Событие | Источник | Когда генерируется |
|---|---|---|
| `preview:button-click` | `CardPreview` | При нажатии на кнопку покупки или удаления товара. |
| `order:payment-change` | `OrderForm` | При выборе способа оплаты. |
| `order:address-change` | `OrderForm` | При изменении адреса доставки. |
| `order:submit` | `OrderForm` | При отправке первой формы. |
| `contacts:email-change` | `ContactsForm` | При изменении электронной почты. |
| `contacts:phone-change` | `ContactsForm` | При изменении номера телефона. |
| `contacts:submit` | `ContactsForm` | При отправке второй формы. |

#### Обработка событий в Presenter

- `catalog:changed` — получает актуальный каталог из `CatalogModel` и обновляет галерею.
- `basket:changed` — обновляет счётчик корзины.
- `buyer:changed` — обновляет состояние и ошибки обеих форм.
- `preview:button-click` — добавляет товар в корзину или удаляет его из неё.
- `order:payment-change` — обновляет способ оплаты в `BuyerModel`.
- `order:address-change` — обновляет адрес доставки в `BuyerModel`.
- `order:submit` — проверяет первую форму и открывает форму контактов.
- `contacts:email-change` — обновляет электронную почту покупателя.
- `contacts:phone-change` — обновляет номер телефона покупателя.
- `contacts:submit` — запускает итоговую проверку и отправку заказа.

Событие `preview:changed` генерируется моделью каталога при выборе товара. Отдельная подписка на него в Presenter не используется: отображение выбранного товара выполняется непосредственно функцией `openPreview()`.

Открытие корзины, удаление товара из неё и закрытие модального окна также могут выполняться через переданные функции обратного вызова, без генерации отдельных событий `EventEmitter`.

## Оформление заказа

Оформление заказа проходит в несколько этапов:

1. Пользователь добавляет товары в корзину.
2. Открывает корзину и переходит к оформлению заказа.
3. Выбирает способ оплаты и вводит адрес доставки.
4. Presenter проверяет данные первой формы через `BuyerModel` и открывает форму контактных данных.
5. Пользователь вводит электронную почту и номер телефона.
6. Presenter выполняет итоговую проверку через `BuyerModel.validateBuyerData()`.
7. Формируется объект `IOrder`, содержащий способ оплаты, контактные данные, адрес, общую стоимость и идентификаторы товаров.
8. `ApiService.createOrder()` отправляет заказ на сервер.
9. При успешном ответе очищаются корзина и данные покупателя, после чего отображается окно успешного оформления заказа.
10. Если сервер возвращает ошибку, она обрабатывается в блоке `catch`, а пользователю отображается сообщение об ошибке.
