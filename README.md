# Проектная работа «Веб-ларёк»

## Описание проекта

«Веб-ларёк» — интернет-магазин, в котором пользователь может просматривать каталог товаров, открывать карточки с подробной информацией, добавлять товары в корзину и оформлять заказ.

Проект реализован с использованием архитектурного подхода **MVP (Model–View–Presenter)** и событийной модели взаимодействия между компонентами.

## Технологии

- HTML5
- SCSS
- TypeScript
- Vite

## Функциональность

- Загрузка каталога товаров с сервера.
- Отображение карточек товаров.
- Просмотр подробной информации о товаре.
- Добавление и удаление товаров из корзины.
- Отображение количества товаров в корзине.
- Подсчёт общей стоимости заказа.
- Выбор способа оплаты.
- Указание адреса доставки.
- Ввод контактных данных: email и телефон.
- Проверка заполненности обязательных полей.
- Отправка заказа на сервер.
- Отображение окна успешного оформления заказа.

## Установка и запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/zzsahazz/weblarek.git
```

### 2. Переход в папку проекта

```bash
cd weblarek
```

### 3. Установка зависимостей

```bash
npm install
```

### 4. Настройка переменных окружения

В корне проекта необходимо создать файл `.env` и указать адрес API:

```env
VITE_API_ORIGIN=https://larek.ffapi.ru
```

```bash
npm run dev
```

После запуска приложение будет доступно по адресу, который укажет Vite в терминале (обычно http://localhost:5173/).

### 6. Сборка проекта

```bash
npm run build
```

Собранная версия проекта будет находиться в папке `dist`.

## Архитектура проекта

В проекте используется архитектура **MVP (Model–View–Presenter)**.

- **Model** — отвечает за хранение и изменение данных приложения.
- **View** — отвечает за отображение данных и взаимодействие с пользователем.
- **Presenter** — связывает Model и View, обрабатывает события и управляет логикой приложения.

Для взаимодействия компонентов используется класс `EventEmitter`, реализующий событийную модель.

Модели изменяют своё состояние и генерируют события. Presenter подписывается на эти события, получает актуальные данные через методы моделей и обновляет представление.

## Базовые классы

### Api.ts

Класс `Api` отвечает за базовое взаимодействие с сервером.

Основные возможности:

- отправка HTTP-запросов;
- получение данных;
- отправка данных на сервер;

### Component.ts

Базовый абстрактный класс для компонентов представления.

Предоставляет общие методы для работы с DOM-элементами и их отображения.

### Events.ts

Содержит интерфейс `IEvents` и класс `EventEmitter`.

`EventEmitter` реализует событийную модель приложения и предоставляет методы:

- `on()` — подписка на событие;
- `off()` — отписка от события;
- `emit()` — генерация события;
- `trigger()` — создание обработчика события.

## Модели данных (Model)

### CatalogModel.ts

Модель каталога товаров.

Отвечает за:

- хранение списка товаров;
- сохранение полученных с сервера товаров;
- получение списка товаров;
- поиск товара по идентификатору;
- хранение выбранного товара для предварительного просмотра.

Основные методы:

- `saveProducts(products)` — сохраняет список товаров;
- `getProducts()` — возвращает список товаров;
- `findProduct(productId)` — ищет товар по идентификатору;
- `chooseProduct(product)` — устанавливает выбранный товар;
- `getChosenProduct()` — возвращает выбранный товар.

Генерируемые события:

- `catalog:changed` — список товаров изменён;
- `preview:changed` — выбранный товар изменён.

### BasketModel.ts

Модель корзины.

Отвечает за хранение товаров, добавление и удаление товаров, подсчёт количества и общей стоимости заказа.

Основные методы:

- `getProducts()` — возвращает товары корзины;
- `addProduct(product)` — добавляет товар в корзину, если его там ещё нет;
- `removeProduct(productId)` — удаляет товар по идентификатору;
- `clearBasket()` — очищает корзину;
- `getTotalPrice()` — возвращает общую стоимость товаров;
- `getProductCount()` — возвращает количество товаров;
- `hasProduct(productId)` — проверяет наличие товара в корзине.

Генерируемое событие:

- `basket:changed` — содержимое корзины изменено.

### BuyerModel.ts

Модель данных покупателя.

Отвечает за хранение контактных данных и информации о доставке.

Основные методы:

- `updateBuyerData(data)` — обновляет данные покупателя;
- `getBuyerData()` — возвращает текущие данные покупателя;
- `clearBuyerData()` — очищает данные покупателя;
- `validateBuyerData()` — проверяет заполненность обязательных полей.

Проверяются следующие данные:

- выбран ли способ оплаты;
- указан ли адрес доставки;
- заполнен ли email;
- заполнен ли телефон.

Генерируемое событие:

- `buyer:changed` — данные покупателя изменены.

## Presenter (main.ts)

Файл `main.ts` выполняет роль Presenter и связывает модели данных с компонентами представления.

В нём создаются экземпляры моделей, компонентов View, API-сервиса и менеджера событий.

Presenter подписывается на события приложения и выполняет необходимые действия.

### Основные функции Presenter

- `renderCatalog()` — получает товары из модели каталога, создаёт карточки и передаёт их в галерею.
- `openPreview(product)` — устанавливает выбранный товар в модели каталога.
- `renderBasket()` — получает товары из корзины, создаёт элементы списка и обновляет отображение корзины.
- `openBasket()` — открывает модальное окно с корзиной.
- `openOrder()` — открывает первую форму оформления заказа.
- `openContacts()` — открывает форму контактных данных.
- `updateForms()` — обновляет данные форм, ошибки валидации и доступность кнопок отправки.
- `submitOrder()` — формирует заказ, отправляет его на сервер и обрабатывает результат оформления.

### Обработка событий

Presenter обрабатывает события приложения следующим образом:

| Событие | Действие Presenter |
|---|---|
| `catalog:changed` | Обновляет каталог товаров |
| `preview:changed` | Получает выбранный товар и отображает его в модальном окне |
| `basket:changed` | Обновляет счётчик корзины и её содержимое |
| `buyer:changed` | Обновляет формы и результаты валидации |
| `card:select` | Открывает предварительный просмотр товара |
| `preview:button-click` | Добавляет товар в корзину или удаляет его из неё |
| `basket:open` | Открывает корзину |
| `basket:delete` | Удаляет выбранный товар из корзины |
| `basket:order` | Открывает первую форму оформления заказа |
| `order:payment-change` | Обновляет способ оплаты в модели покупателя |
| `order:address-change` | Обновляет адрес доставки в модели покупателя |
| `order:submit` | Переходит к форме контактных данных |
| `contacts:email-change` | Обновляет email покупателя |
| `contacts:phone-change` | Обновляет телефон покупателя |
| `contacts:submit` | Запускает отправку заказа |
| `success:close` | Закрывает модальное окно |

## Работа с заказом

Оформление заказа состоит из нескольких этапов:

1. Пользователь добавляет товары в корзину.
2. Открывает корзину и нажимает кнопку оформления заказа.
3. Выбирает способ оплаты и указывает адрес доставки.
4. После проверки обязательных полей переходит к форме контактных данных.
5. Указывает email и телефон.
6. После проверки данных заказ отправляется на сервер.
7. При успешном ответе сервера корзина и данные покупателя очищаются, а пользователь видит окно успешного оформления заказа.

Если сервер возвращает ошибку, приложение обрабатывает её и не сообщает об успешном оформлении заказа.

## Итог

В проекте реализовано разделение логики приложения, данных и представления. Использование архитектуры MVP и событийной модели позволяет разделить ответственность между компонентами и упростить их взаимодействие и дальнейшее развитие проекта.
