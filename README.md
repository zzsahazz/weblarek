# Проектная работа «Веб-ларёк»

## Описание проекта

Проект реализован с использованием архитектурного подхода MVP (Model–View–Presenter) и событийной модели взаимодействия между компонентами.

## Технологии

- HTML5
- SCSS
- TypeScript
- Vite

## Функциональность

- Загрузка каталога товаров с сервера.
- Отображение карточек товаров.
- Просмотр подробной информации о товаре.
- Добавление товаров в корзину.
- Удаление товаров из корзины.
- Подсчёт количества товаров и общей стоимости.
- Выбор способа оплаты.
- Ввод адреса доставки.
- Ввод контактных данных покупателя.
- Валидация данных перед оформлением заказа.
- Отправка заказа на сервер.
- Отображение результата оформления заказа.

## Архитектура проекта

В проекте используется архитектура MVP (Model–View–Presenter).

Она разделяет приложение на три основные части:

### Model — модели данных

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.
View - слой представления, отвечает за отображение данных на странице.
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

### View — представление

Отвечает за отображение информации и взаимодействие с пользователем.
View-компоненты не содержат бизнес-логики. Они отображают данные и передают действия пользователя через события или функции обратного вызова.

### Presenter — посредник

Роль Presenter выполняет файл `main.ts`.

Он связывает модели и представления, обрабатывает события, обновляет интерфейс, управляет переходами между формами и организует отправку заказа на сервер.

### Взаимодействие компонентов

1. Пользователь выполняет действие в интерфейсе.
2. View-компонент генерирует событие или вызывает переданную функцию.
3. Presenter обрабатывает действие.
4. При необходимости Presenter обращается к модели.
5. Модель изменяет данные и генерирует событие об изменении состояния.
6. Presenter получает событие и обновляет соответствующее представление.

Для обмена событиями используется `EventEmitter`.

## Базовые классы

### Component

Базовый класс для View-компонентов.
Предоставляет общую функциональность для работы с HTML-элементами и обновления интерфейса. Остальные компоненты представления наследуются от него.

### Api

Базовый класс для выполнения HTTP-запросов к серверу.
Предоставляет методы `get()` и `post()` для получения и отправки данных.

### EventEmitter

Класс для организации событийного взаимодействия между компонентами приложения.
Позволяет подписываться на события, генерировать их и обрабатывать изменения состояния приложения.

## Типы данных

Основные интерфейсы, типы и перечисления проекта находятся в `src/types/index.ts`.

### ApiPostMethods

Тип HTTP-методов для отправки запросов:

```ts
export type ApiPostMethods = 'POST' | 'PUT' | 'DELETE';
```

### IApi

Интерфейс базового API-клиента.

Описывает методы:

- `get<T>(uri)` — получение данных с сервера.
- `post<T>(uri, data, method?)` — отправка данных на сервер.

### BuyerErrors

Тип для хранения ошибок валидации данных покупателя.

```ts
export type BuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Позволяет хранить сообщения об ошибках для отдельных полей интерфейса `IBuyer`.

### TPayment

Перечисление способов оплаты:

```ts
export enum TPayment {
    CARD = 'card',
    CASH = 'cash',
}
```

- `CARD` — оплата картой.
- `CASH` — оплата наличными.

### IProduct

Интерфейс товара:

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Идентификатор товара |
| `description` | `string` | Описание товара |
| `image` | `string` | Изображение товара |
| `title` | `string` | Название товара |
| `category` | `string` | Категория товара |
| `price` | `number \| null` | Цена товара или `null`, если товар недоступен для покупки |

### IBuyer

Интерфейс данных покупателя:

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
id — уникальный идентификатор товара.
description — подробное описание товара.
image — имя файла изображения; полная ссылка получается добавлением его к CDN_URL.
title — название товара.
category — категория товара (софт-скил, хард-скил, кнопка, дополнительное, другое).
price — цена в синапсах; null, если у товара нет цены и его нельзя купить.

### IProducts

Интерфейс ответа сервера с каталогом товаров:

interface IProductsResponse {
  total: number;
  items: IProduct[];
}
### IOrder

Интерфейс данных заказа:

interface IOrder {
    payment: TPayment;

    items: string[];
}

### IOrderResult

Интерфейс результата оформления заказа:

interface IOrderResult {
    id: string;
    total: number;
}

### TCard

Тип данных для карточки товара.

type TCard = Pick<IProduct, 'title' | 'price'> & {
    category?: string;
    image?: string;
    description?: string;
};

### TCardCatalog

Тип данных карточки товара в каталоге.

type TCardCatalog = TCard & Pick<IProduct, 'category' | 'image'>;


### ICardActions

Интерфейс действий карточки:

interface ICardActions {
    onClick?: () => void;
}


## Модели данных (Model)

### CatalogModel

Класс `CatalogModel` отвечает за хранение и управление каталогом товаров, а также за выбор товара для подробного просмотра.

**Поля класса:**

protected productList: IProduct[] = [];
protected chosenProduct: IProduct | null = null;

constructor(protected events: IEvents)

**Конструктор:**

`constructor(events: IEvents)` - Принимает систему событий для оповещения об изменениях каталога и выбранного товара.

**Методы:**

- `saveProducts(products: IProduct[])` — сохраняет массив товаров и генерирует событие `catalog:changed`.
- `getProducts()` — возвращает копию массива товаров.
- `findProduct(productId: string)` — ищет товар по идентификатору.
- `chooseProduct(product: IProduct | null)` — устанавливает выбранный товар и генерирует событие `preview:changed`.
- `getChosenProduct()` — возвращает выбранный товар.

**События:**

- `catalog:changed` — изменение каталога товаров.
- `preview:changed` — изменение выбранного товара для предварительного просмотра.

### BasketModel

Класс `BasketModel` отвечает за управление товарами в корзине и расчёт общей стоимости.

**Поля класса:**

- `basketProducts: IProduct[]` — массив товаров в корзине.
- `events: IEvents` — система событий.

**Конструктор:**

`constructor(events: IEvents)`

Принимает систему событий.

**Методы:**

- `getProducts()` — возвращает копию массива товаров корзины.
- `addProduct(product: IProduct)` — добавляет товар, если его ещё нет в корзине.
- `removeProduct(productId: string)` — удаляет товар по идентификатору.
- `clearBasket()` — очищает корзину.
- `getTotalPrice()` — рассчитывает общую стоимость товаров. Если цена товара равна `null`, для расчёта используется `0`.
- `getProductCount()` — возвращает количество товаров в корзине.
- `hasProduct(productId: string)` — проверяет наличие товара в корзине.

**События:**

- `basket:changed` — генерируется при фактическом изменении содержимого корзины.

Событие передаёт массив актуальных товаров в свойстве `products`.

### BuyerModel

Класс `BuyerModel` отвечает за хранение данных покупателя и их валидацию перед оформлением заказа.

**Поля класса:**

- `paymentMethod: TPayment | ''` — выбранный способ оплаты.
- `deliveryAddress: string` — адрес доставки.
- `emailAddress: string` — электронная почта.
- `phoneNumber: string` — номер телефона.
- `events: IEvents` — система событий.

**Конструктор:**

`constructor(events: IEvents)`

Принимает систему событий.

**Методы:**

- `updateBuyerData(data: Partial<IBuyer>)` — обновляет переданные данные покупателя.
- `getBuyerData()` — возвращает текущие данные покупателя.
- `clearBuyerData()` — очищает все данные покупателя.
- `validateBuyerData()` — проверяет корректность заполнения обязательных полей и возвращает объект с ошибками типа `BuyerErrors`.

**Проверки валидации:**

- Выбран ли способ оплаты.
- Указан ли адрес доставки.
- Заполнена ли электронная почта и соответствует ли она базовому формату email.
- Заполнен ли номер телефона и соответствует ли он заданному формату.

**События:**

- `buyer:changed` — генерируется при изменении или очистке данных покупателя.

Событие передаёт актуальные данные покупателя в свойстве `buyer`.

## API-сервис

### ApiService

Класс `ApiService` является дополнительным уровнем взаимодействия между приложением и API.

Он использует интерфейс `IApi` и предоставляет методы, предназначенные непосредственно для работы с данными интернет-магазина.

**Конструктор:**

`constructor(api: IApi)`

Принимает экземпляр API-клиента.

**Методы:**

- `getProducts(): Promise<IProducts>` — отправляет GET-запрос на `/product/` и получает каталог товаров.
- `createOrder(order: IOrder): Promise<IOrderResult>` — отправляет POST-запрос на `/order/` с данными заказа и получает результат оформления.

## Компоненты представления (View)

### Gallery

Класс `Gallery` отвечает за отображение карточек товаров в каталоге.

**Интерфейс IGallery:**

- `catalog: HTMLElement[]` — массив HTML-элементов карточек товаров.

**Конструктор:**

`constructor(container: HTMLElement)`

Принимает HTML-контейнер галереи.

**Сеттер:**

- `catalog(items: HTMLElement[])` — заменяет содержимое галереи переданными карточками с помощью `replaceChildren()`.

Компонент не создаёт карточки и не загружает товары с сервера. Он только отображает переданные HTML-элементы.

### Card

Базовый класс карточки товара.

Используется для повторного применения общей логики отображения названия и цены в разных видах карточек.

**Поля класса:**

- `titleElement: HTMLElement` — элемент названия товара.
- `priceElement: HTMLElement` — элемент цены товара.

**Конструктор:**

`constructor(container: HTMLElement)`

Принимает HTML-элемент карточки и находит элементы названия и цены.

**Сеттеры:**

- `title(value: string)` — устанавливает название товара.
- `price(value: number | null)` — устанавливает отображение цены товара. При значении `null` отображается текст «Бесценно».

### CardCatalog

Класс `CardCatalog` отвечает за отображение карточки товара в каталоге.

**Наследование:** расширяет класс `Card<TCardCatalog>`.

**Поля класса:**

- `categoryElement: HTMLElement` — элемент категории товара.
- `imageElement: HTMLImageElement` — изображение товара.

**Конструктор:**

`constructor(container: HTMLElement, actions?: ICardActions)`

Принимает HTML-элемент карточки и необязательный объект действий. Находит элементы категории и изображения. Если передан `onClick`, устанавливает обработчик нажатия на карточку.

**Сеттеры:**

- `category(value: string)` — устанавливает название категории и соответствующий CSS-модификатор из `categoryMap`.
- `image(value: string)` — устанавливает изображение товара, добавляя к пути адрес CDN из `CDN_URL`.

Также наследует сеттеры `title` и `price` от класса `Card`.

### CardPreview

Класс `CardPreview` отвечает за отображение подробной информации о товаре в модальном окне.

**Наследование:** расширяет класс `Card<TCardCatalog>`.

**Поля класса:**

- `events: IEvents` — система событий.
- `categoryElement: HTMLElement` — элемент категории.
- `imageElement: HTMLImageElement` — изображение товара.
- `descriptionElement: HTMLElement` — описание товара.
- `buttonElement: HTMLButtonElement` — кнопка действия с товаром.

**Конструктор:**

`constructor(events: IEvents, container: HTMLElement)`

Принимает систему событий и HTML-элемент карточки. Находит необходимые элементы и устанавливает обработчик на кнопку действия.

**Сеттеры:**

- `category(value: string)` — устанавливает категорию и соответствующий CSS-модификатор.
- `image(value: string)` — устанавливает изображение товара и альтернативный текст на основе названия.
- `description(value: string)` — устанавливает описание товара.
- `buttonText(value: string)` — изменяет текст кнопки.
- `buttonDisabled(value: boolean)` — управляет доступностью кнопки.

Также наследует сеттеры `title` и `price` от класса `Card`.

**События:**

- `preview:button-click` — генерируется при нажатии на кнопку действия с товаром.

Компонент не добавляет и не удаляет товары самостоятельно. Этим занимается Presenter совместно с `BasketModel`.

### Modal

Класс `Modal` отвечает за управление модальным окном приложения.

**Поля класса:**

- `events: IEvents` — система событий.
- `closeButton: HTMLButtonElement` — кнопка закрытия.
- `contentElement: HTMLElement` — контейнер содержимого модального окна.

**Конструктор:**

`constructor(events: IEvents, container: HTMLElement)`

Принимает систему событий и HTML-контейнер модального окна. Находит необходимые элементы и устанавливает обработчики закрытия.

**Сеттер:**

- `content(element: HTMLElement)` — заменяет содержимое модального окна переданным HTML-элементом.

**Методы:**

- `open()` — открывает модальное окно, добавляя класс `modal_active`, и блокирует прокрутку страницы классом `page__wrapper_locked`.
- `close()` — закрывает окно и восстанавливает прокрутку страницы.

**События:**

- `modal:close` — генерируется при нажатии на кнопку закрытия, фон модального окна или клавишу `Escape`, если окно открыто.

### BasketItem

Класс `BasketItem` отвечает за отображение одного товара в корзине.

**Интерфейс IBasketItem:**

- `index: number` — порядковый номер товара.

**Наследование:** расширяет класс `Card<IBasketItem>` и наследует отображение названия и цены.

**Поля класса:**

- `indexElement: HTMLElement` — элемент порядкового номера.
- `deleteButton: HTMLButtonElement` — кнопка удаления товара.

**Конструктор:**

`constructor(container: HTMLElement, onDelete: () => void)`

Принимает HTML-элемент карточки и функцию обратного вызова для удаления товара. Находит необходимые элементы и устанавливает обработчик на кнопку удаления.

**Сеттер:**

- `index(value: number)` — устанавливает порядковый номер товара.

Компонент не удаляет товар самостоятельно. Он вызывает переданную функцию `onDelete`, а фактическое удаление выполняется через `BasketModel`.

### BasketView

Класс `BasketView` отвечает за отображение содержимого корзины.

**Интерфейс IBasketView:**

- `items: HTMLElement[]` — массив HTML-элементов карточек товаров.
- `total: number` — общая стоимость товаров.

**Поля класса:**

- `listElement: HTMLElement` — контейнер списка товаров.
- `totalElement: HTMLElement` — элемент общей стоимости.
- `orderButton: HTMLButtonElement` — кнопка перехода к оформлению заказа.

**Конструктор:**

`constructor(container: HTMLElement, onOrder: () => void)`

Принимает HTML-элемент корзины и функцию обратного вызова для перехода к оформлению заказа. Находит необходимые элементы и устанавливает обработчик на кнопку оформления.

**Сеттеры:**

- `items(items: HTMLElement[])` — отображает карточки товаров. Если массив пустой, выводит сообщение «Корзина пуста». Также блокирует кнопку оформления, если товаров нет.
- `total(value: number)` — отображает общую стоимость в формате `значение синапсов`.

При нажатии на кнопку вызывается переданная функция `onOrder`.

### OrderForm

Класс `OrderForm` отвечает за первую часть оформления заказа: выбор способа оплаты и ввод адреса доставки.

**Поля класса:**

- `events: IEvents` — система событий.
- `cardButton: HTMLButtonElement` — кнопка выбора оплаты картой.
- `cashButton: HTMLButtonElement` — кнопка выбора оплаты наличными.
- `addressInput: HTMLInputElement` — поле ввода адреса.
- `submitButton: HTMLButtonElement` — кнопка перехода к следующему этапу.
- `errorsElement: HTMLElement` — элемент отображения ошибок.
- `paymentMethod: TPayment | ''` — выбранный способ оплаты.

**Конструктор:**

`constructor(events: IEvents, container: HTMLFormElement)`

Принимает систему событий и HTML-форму. Находит необходимые элементы и устанавливает обработчики действий пользователя.

**Методы:**

- `setPayment(payment: TPayment)` — устанавливает способ оплаты, обновляет активное состояние кнопок и генерирует событие.
- `updateSubmitButton()` — проверяет наличие выбранного способа оплаты и заполненного адреса, управляя доступностью кнопки.
- `clear()` — сбрасывает способ оплаты, адрес и текст ошибок.

**Сеттеры:**

- `errors(value: string)` — устанавливает текст ошибки.
- `address(value: string)` — заполняет поле адреса и обновляет состояние кнопки.
- `payment(value: TPayment)` — устанавливает способ оплаты через `setPayment()`.

**События:**

- `order:payment-change` — изменение способа оплаты.
- `order:address-change` — изменение адреса доставки.
- `order:submit` — отправка первой формы для перехода к контактным данным.

Кнопка перехода дальше становится доступной только после выбора способа оплаты и заполнения адреса.

### ContactsForm

Класс `ContactsForm` отвечает за вторую часть оформления заказа: ввод электронной почты и номера телефона.

**Поля класса:**

- `events: IEvents` — система событий.
- `emailInput: HTMLInputElement` — поле ввода электронной почты.
- `phoneInput: HTMLInputElement` — поле ввода телефона.
- `submitButton: HTMLButtonElement` — кнопка отправки заказа.
- `errorsElement: HTMLElement` — элемент отображения ошибок.

**Конструктор:**

`constructor(events: IEvents, container: HTMLFormElement)`

Принимает систему событий и HTML-форму. Находит необходимые элементы и устанавливает обработчики изменения контактных данных и отправки формы.

**Методы:**

- `updateSubmitButton()` — проверяет, заполнены ли поля электронной почты и телефона, и управляет доступностью кнопки.
- `clear()` — очищает контактные поля и ошибки, обновляет состояние кнопки.

**Сеттеры:**

- `errors(value: string)` — устанавливает текст ошибки.
- `email(value: string)` — заполняет поле электронной почты и обновляет состояние кнопки.
- `phone(value: string)` — заполняет поле телефона и обновляет состояние кнопки.

**События:**

- `contacts:email-change` — изменение электронной почты.
- `contacts:phone-change` — изменение номера телефона.
- `contacts:submit` — отправка формы контактных данных.

Компонент выполняет предварительную проверку заполненности полей. Полная проверка формата электронной почты и телефона выполняется в `BuyerModel.validateBuyerData()`.

## Presenter — main.ts

Файл `main.ts` выполняет роль Presenter и связывает все части приложения.

В нём создаются экземпляры моделей, API-клиента и View-компонентов, настраиваются подписки на события и определяется логика взаимодействия между ними.

- `Gallery` — представление каталога.

### Оформление заказа

Оформление заказа проходит в несколько этапов:

1. Пользователь добавляет товары в корзину.
2. Открывает корзину и переходит к оформлению заказа.
3. Выбирает способ оплаты и вводит адрес доставки.
4. Presenter проверяет данные и открывает форму контактных данных.
5. Пользователь вводит электронную почту и номер телефона.
6. Presenter выполняет полную валидацию через `BuyerModel.validateBuyerData()`.
7. Формируется объект `IOrder`, содержащий способ оплаты, контактные данные, адрес, общую стоимость и идентификаторы товаров.
8. `ApiService.createOrder()` отправляет заказ на сервер.
9. При успешном ответе очищаются корзина и данные покупателя, после чего отображается окно успешного оформления заказа.

Если сервер возвращает ошибку, она обрабатывается в блоке `catch`.
