## Структура проекта

- `src/` — исходные файлы проекта.
- `src/components/` — классы приложения.
- `src/components/Models/` — модели данных.

- `src/components/Models/CatalogModel.ts` — модель каталога товаров.
- `src/components/Models/BasketModel.ts` — модель корзины.

- `src/utils/data.ts` — тестовые данные товаров.

## Архитектура приложения

В проекте используется архитектурный парадигме MVP (Model-View-Presenter).

В первой части проектной работы основное внимание уделено моделям данных и коммуникационному слою. Модели отвечают за хранение и обработку данных, а коммуникационный класс обеспечивает взаимодействие с сервером.

### Базовые классы

#### Api

Содержит в себе базовую логику отправки запросов.

**Конструктор:**

- `constructor(baseUrl: string, options?: RequestInit)` — принимает базовый адрес сервера и дополнительные параметры запросов.

**Методы:**

- `get(uri: string): Promise<object>` — выполняет GET-запрос и возвращает данные сервера.
- `post(uri: string, data: object, method?: ApiPostMethods): Promise<object>` — отправляет данные на сервер методом POST, PUT или DELETE.
- `handleResponse(response: Response): Promise<object>` — обрабатывает ответ сервера и проверяет его корректность.

### Модели данных

Модели отвечают за хранение, получение, изменение и проверку данных приложения. Они не занимаются отображением информации на странице.

#### CatalogModel

Модель каталога товаров.

**Конструктор:**

- Отсутствует. Поля инициализируются непосредственно при создании экземпляра класса.

**Поля:**

- `productList: IProduct[]` — массив всех товаров, полученных из каталога.
- `chosenProduct: IProduct | null` — товар, выбранный для подробного отображения. Если товар не выбран, значение равно `null`.

**Методы:**

- `saveProducts(products: IProduct[]): void` — сохраняет переданный массив товаров в каталоге.
- `getProducts(): IProduct[]` — возвращает массив всех товаров.
- `findProduct(productId: string): IProduct | undefined` — находит и возвращает товар по его идентификатору. Если товар не найден, возвращает `undefined`.
- `chooseProduct(product: IProduct | null): void` — сохраняет товар, выбранный для подробного отображения.
- `getChosenProduct(): IProduct | null` — возвращает выбранный товар или `null`, если товар не выбран.

#### BasketModel

Модель корзины покупателя.

**Конструктор:**

- Отсутствует. Массив товаров инициализируется при создании экземпляра класса.

**Поля:**

- `basketProducts: IProduct[]` — массив товаров, добавленных покупателем в корзину.

**Методы:**

- `getProducts(): IProduct[]` — возвращает массив товаров, находящихся в корзине.
- `addProduct(product: IProduct): void` — добавляет товар в корзину, если такого товара там ещё нет.
- `removeProduct(productId: string): void` — удаляет товар из корзины по его идентификатору.
- `clearBasket(): void` — полностью очищает корзину.
- `getTotalPrice(): number` — вычисляет и возвращает общую стоимость товаров в корзине. Товары без цены учитываются как товары стоимостью 0.
- `getProductCount(): number` — возвращает количество товаров в корзине.
- `hasProduct(productId: string): boolean` — проверяет наличие товара в корзине по его идентификатору.

#### BuyerModel

Модель данных покупателя.

**Конструктор:**

- Отсутствует. Все поля инициализируются значениями по умолчанию.

**Поля:**

- `paymentMethod: TPayment | ''` — выбранный способ оплаты. Может принимать значения `card`, `cash` или пустую строку, если способ оплаты не выбран.
- `deliveryAddress: string` — адрес доставки покупателя.
- `emailAddress: string` — электронная почта покупателя.
- `phoneNumber: string` — номер телефона покупателя.

**Методы:**

- `updateBuyerData(data: Partial<IBuyer>): void` — обновляет данные покупателя. Позволяет изменять как все поля одновременно, так и отдельные поля без потери остальных данных.
- `getBuyerData(): Partial<IBuyer>` — возвращает объект с текущими данными покупателя.
- `clearBuyerData(): void` — очищает все данные покупателя и возвращает поля к начальным значениям.
- `validateBuyerData(): BuyerErrors` — проверяет данные покупателя. Проверяет заполненность способа оплаты, адреса, email и телефона, а также формат email и телефона. Возвращает объект с сообщениями об ошибках. Если ошибок нет, возвращает пустой объект.

### Коммуникационный слой

#### ApiService

Класс `ApiService` отвечает за взаимодействие приложения с сервером. Использует композицию: получает экземпляр базового API-класса через конструктор и вызывает его методы для выполнения запросов.

**Конструктор:**

- `constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi`, для выполнения HTTP-запросов.

**Поля:**

- `api: IApi` — экземпляр API-класса, используемый для отправки запросов на сервер.

**Методы:**

- `getProducts(): Promise<IProducts>` — выполняет GET-запрос к эндпоинту `/product/` и возвращает объект с массивом товаров и их общим количеством.
- `createOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос к эндпоинту `/order/`, передаёт данные заказа на сервер и возвращает результат оформления заказа.

## Типы и интерфейсы

Все основные типы и интерфейсы приложения описаны в файле `src/types/index.ts`.

- `ApiPostMethods` — тип, определяющий доступные HTTP-методы: `POST`, `PUT`, `DELETE`.
- `IApi` — интерфейс базового API-класса, описывающий методы получения и отправки данных.
- `IProduct` — интерфейс товара, содержащий идентификатор, описание, изображение, название, категорию и цену.
- `IBuyer` — интерфейс данных покупателя: способ оплаты, email, телефон и адрес доставки.
- `IProducts` — интерфейс ответа сервера со списком товаров и их общим количеством.
- `IOrder` — интерфейс данных заказа, передаваемых на сервер.
- `IOrderResult` — интерфейс результата оформления заказа, получаемого от сервера.
- `BuyerErrors` — тип объекта, содержащего сообщения об ошибках валидации данных покупателя.
- `TPayment` — перечисление доступных способов оплаты: картой (`card`) или наличными (`cash`).

## Проверка работы

В файле `src/main.ts` создаются экземпляры всех трёх моделей данных и проверяются их методы с помощью `console.log`.

Для проверки используются тестовые данные товаров из файла `src/utils/data.ts`.

После проверки моделей выполняется GET-запрос к серверу через класс `ApiService`. Полученный массив товаров сохраняется в `CatalogModel`, после чего результат выводится в консоль.

Таким образом проверяется самостоятельная работа моделей данных и взаимодействие коммуникационного слоя с сервером.
